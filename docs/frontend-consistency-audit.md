# 前端标题、半透明表面、刷新与窗口裁剪审查

## 用户确定的方向

统一全前端半透明表面，包括小弹窗、标准卡片和标题图标区域；修复变更后仍显示旧缓存的路径。
系统边框加自绘标题栏（system_shadow）禁用页面窗口圆角，只有纯自绘 custom 模式允许窗口裁剪。

后续 A 方案调整：普通卡片取消统一强制模糊，弹窗保留独立模糊。按用户最新要求，
卡片和控件透明度保留原值，不采用新增的嵌套卡片轻底色。启动预取改为页面按需查询，
搜索缓存和节点调度由后端负责。详细记录见主仓库 `docs/backend-startup-cache-and-surface-correction-plan.md`。
下方验证结果记录前一轮实现，最终变更以 A 方案及用户后续透明度回退要求为准。

## 已确认问题与实施点

| 范围                       | 问题                                                          | 修复                                                       |
| -------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| 更新、微软登录弹窗         | 上次增加不透明底色覆盖共享表面                                | 移除覆盖，使用共享半透明表面和模糊保证可读性               |
| 标准卡片、设置分组、小弹窗 | 标题图标非统一默认；缺省 content 弹窗没有图标                 | 共享标题默认图标并保留显式业务图标，统一尺寸和颜色         |
| Classic / Folia / Naive UI | ecl-surface 固定 alpha；Naive UI 使用固定色，透明度设置不一致 | 共享透明度变量、控件和浮层表面变量，覆盖两个皮肤和亮暗模式 |
| 任务队列、错误详情等       | 局部 bg-base 实底打断半透明体系                               | 表面使用语义半透明变量，保留背景画布和状态色的用途         |
| 衣柜与账户后台通知         | 衣柜普通加载命中 ready 缓存；账户变更未接入共享 Store         | 强制刷新衣柜变更，订阅账户变更并安全更新共享状态           |
| 插件列表                   | 强制刷新复用旧在途请求，状态通知可被旧快照吞掉                | 丢弃变更之前的快照并完成后续刷新                           |
| Java 列表                  | 强制刷新 / 失效仍可能命中在途扫描                             | 版本标记及强制请求，旧响应不能覆盖最新扫描                 |
| 实例扫描                   | 失效后的旧请求仍可回填缓存                                    | 每路径版本标记、在途合并和最新响应保护                     |
| 通用自动刷新缓存           | 并发请求可倒序覆盖；refresh 仅删除不请求数据                  | 在途合并、强制刷新及旧结果保护，刷新执行获取               |
| 窗口外观                   | 根容器默认裁圆角；圆角禁用状态仍显示保存值                    | 根容器默认方形，custom 才启用；系统模式禁用裁剪和圆角修改  |

进一步确认并修复：

- 挂载容器与 App 页面根节点重复使用 `id="app"`，窗口模式只写入内层。外层仍裁圆角；现在保留唯一挂载 ID，并在挂载前写入实际窗口模式。
- 通用缓存是非响应式 Map，同一个键在不同组件中显示不同快照；新增作用域订阅与分组失效通知，失效前的请求不能重新回填。
- 头像使用相同 URL 时，清理图片缓存没有触发组件重绘；新增响应式版本通知和旧图片请求保护。
- `config:updated` 只更新开发开关，界面、下载、游戏配置仍使用旧状态；现在等待配置写入完成再读取并应用，路径变化触发实例刷新。
- 原生生产验收发现标准 `backdrop-filter` 被构建优化删除，仅保留 WebView2 不支持的 WebKit 前缀。关闭 Tailwind 的重复优化，使用 esbuild 统一压缩，并以实际 PostCSS + Vite 构建测试检查标准声明。

## 覆盖与验收

检索全部 Vue、CSS、状态 Store、API 缓存和运行时事件路径。
对已确认的数据竞态补充可复现回归测试，并检查已存在版本保护的配置、图片缓存和查询缓存。
执行 pnpm check、pnpm build；原生 Tauri/WebView2 验证 Classic / Folia、亮暗、透明度变化、
标题图标、嵌套弹窗与后台账户刷新、system_shadow 的 app/body 裁剪。
采用隔离数据目录和模拟账户响应，保持用户账户与运行实例。仅本地提交，不推送。

静态审查覆盖 94 个 Vue 文件、56 个 CSS 文件和 TypeScript 数据路径；字面量标题图标均能在图标映射中解析。
新增测试验证刷新竞态、缓存跨组件同步、图片失效重绘、标题图标、实际窗口模式与生产 CSS 兼容性。

最终验证记录见下方；此审查修复已识别问题，不代表对所有真实网络、账户及第三方插件状态穷举验证。
