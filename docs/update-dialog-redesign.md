# 更新弹窗调整方案

## 目标

目标版本与更新内容成为弹窗主体；当前运行方式不支持自更新时提供发布页入口。
保持已有启动提醒、关闭后记录已读版本和关于页手动检查流程。

## 实施

1. 调整 UpdateResultModal 的版本、通道、说明、提示和按钮层级，宽度随窗口限制。
   弹窗使用当前主题的共享半透明表面和模糊层，避免背景文字透出干扰阅读。
   此项按后续用户要求统一调整，验收见 frontend-consistency-audit.md。
2. 通道标签从目标版本判断；完整保留版本号与构建标记。
3. 无说明时显示明确的空状态；长说明局部滚动。
4. 自更新可用时显示“下载并重启”；不可用时显示中性提示与“查看发布页”。
   发布页链接缺失时说明原因，不呈现不可操作的主按钮。
5. 次按钮改为“稍后”，关闭事件继续驱动已有已读记录。
6. 更新过程中禁止关闭和重复提交，未知下载大小也显示进行中的状态。
7. 同步维护六种界面语言。

## 验证

- 组件测试覆盖空说明、发布页入口、链接缺失、关闭事件、下载与应用失败恢复、更新时操作锁定。
- 通道测试覆盖 Alpha、Beta、RC、正式版与构建标记。
- 执行 pnpm check、pnpm build。
- 启动使用独立数据目录的桌面应用，验证实际构建后的布局、滚动、关闭、主题和窄窗口。
- 按仓库要求提交前端及主仓库指针；不推送远端。

## 验证结果

- pnpm check 通过：121 个测试文件通过，627 项测试通过，1 项已有待办。
- pnpm build 通过。
- 生产构建在桌面窗口中通过浅色、深色、长说明滚动、400px 视口、Tab 焦点循环和 Esc 关闭检查。
- 发布页操作传递正确地址；“稍后”和 Esc 关闭均记录已读版本，同版本再次通知不会重开。
- 链接缺失时只显示“稍后”与原因说明。
- 自更新分支使用模拟 IPC 检查未知下载大小、下载及应用期间锁定、重复操作保护和失败后的重试恢复。
  未执行真实更新包下载、安装或重启。
